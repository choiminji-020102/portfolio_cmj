# 풀버전

## ① 배포 환경에서 벡터 DB 생성 실패 & 매 요청 재로딩 · ⭐⭐⭐⭐⭐

**문제 상황** · 로컬에선 잘 되던 RAG 챗봇이 배포 서버에서 Chroma 벡터 DB를 생성하는 단계에서 실패했다. `⟨실제 기억 채울 자리: 이때 뜬 에러 메시지/증상 — 예: permission denied, 경로 못 찾음⟩`

**원인 분석** · 로그를 따라가 보니 두 가지가 겹쳐 있었다.
1. `persist_dir` 기본값이 `"/RAG/chroma"`였다. 앞에 `/`가 붙어 파일시스템 루트 기준 절대경로가 됐고, 로컬에서는 프로젝트 루트에서 실행돼 우연히 통했지만 배포 서버에서는 루트에 쓰기 권한이 없어 DB 생성이 실패했다.
2. 함수 진입부에서 `_vectordb = None`을 매번 실행하고 있었다. 바로 아래에 캐시 히트 분기(`if _vectordb:`)가 있는데도, 그 위에서 캐시를 매번 지워버려 분기가 항상 거짓이 됐다.

**해결 방법 비교** · 경로 문제는 (a) 절대경로를 환경변수로 주입 vs (b) 프로젝트 기준 상대경로로 통일 두 가지를 놓고 봤다. 로컬·배포에서 같은 값으로 동작하게 만드는 이식성을 우선해 (b)를 택했다.

**핵심 변경**
```python
# before → after
persist_dir="/RAG/chroma"   →  persist_dir="RAG/chroma"   # 루트 절대경로 → 상대경로
_vectordb = None            →  # _vectordb = None          # 매 호출 캐시 초기화 제거
```
추가로 `source_folder` 존재 확인·빈 문서 방어·`try/except`를 넣어, 실패 시 원인이 로그에 바로 드러나게 했다.

**적용 후** · 로컬·배포가 동일 경로로 동작하고, 캐시 히트 분기가 실제로 동작해 **첫 요청 이후에는 벡터 DB를 다시 로딩하지 않는다**(반복적인 파일 접근·재임베딩 제거). 경로 없음·빈 문서는 생성 전에 예외로 걸러진다.

**배운 점** · 로컬에서 되던 코드가 배포에서 깨진 원인이 경로·권한 가정이었다는 것, 그리고 캐시 분기가 있어도 그 위에서 매번 초기화하면 무의미하다는 것 — "코드가 있다"와 "동작한다"는 다르다는 걸 확인했다.

## ② 질문 라우팅 아키텍처의 진화 — 3분류에서 4분류, 그리고 역할 재정의 · ⭐⭐⭐⭐⭐

**문제 상황** · 초기 라우팅은 `cow_info / general / rag` 3분류였다. 그런데 (a) "로또 번호 알려줘"처럼 낙농과 무관한 질문에도 챗봇이 성실히 답했고, (b) "103번 소 상태 어때?"(개체 조회)와 "발정 시기 언제야?"(일반 지식)가 명확히 갈리지 않았다.

**1차 대응 — irrelevant 추가** · 무관 질문을 걸러내려고 네 번째 분류 `irrelevant`와 전용 노드 `handle_irrelevant_question`을 추가했다. 무관 질문이면 LLM 호출 없이 "낙농업 관련 질문에만 답할 수 있어요"로 종료시켰다.

**관찰된 부작용** · 실사용을 보니 `irrelevant`가 과하게 작동했다. `⟨실제 기억 채울 자리: 어떤 질문이 거부당하는 걸 봤는지 — 예: "너 아까 뭐랬어?"⟩` 같은, 낙농 질문은 아니지만 챗봇으로서 응대해야 할 UX 대화까지 무관 질문으로 잘려나갔다.

**2차 대응 — 역할 재정의** · 노드를 더 만드는 대신 기존 노드의 책임을 다시 나눴다.
- `rag` → 낙농 지식 질문으로 단일화(문서에 없으면 지식 기반 fallback, ③번과 연결)
- `general` → 잡담용에서 **UX 대화 전담**으로 재정의("이전 질문 뭐였지?", "고마워", "너 누구야?")
- `cow_info` → "그 소·그 아이" 같은 지시어까지 개체 조회로 흡수
- `irrelevant` → 로또·주식 등 **완전 무관**에만 한정

**핵심 코드**
```python
builder.add_conditional_edges("classifier", route_by_answer_type, {
    "rag":        "rag_response",         # 낙농 지식 (문서 없으면 지식 fallback)
    "cow_info":   "cow_info_graph",       # 특정 개체 조회 ("103번 소", "그 소")
    "general":    "general_response",     # UX 대화 ("아까 뭐랬어?", "고마워")
    "irrelevant": "irrelevant_response",  # 완전 무관 (로또·주식)
})
if result not in {"rag", "cow_info", "general", "irrelevant"}:  # LLM 오출력 방어
    result = "irrelevant"
```

**적용 후** · 무관 질문은 LLM 호출 전에 종료되고, UX 대화는 더 이상 오차단되지 않으며, 의도별로 서로 다른 데이터 소스(문서 / 농장 DB / 대화 맥락)에 연결된다.

**배운 점** · 이 항목의 핵심은 "4분류를 만들었다"가 아니라 **분류를 추가했다가 부작용을 관찰하고 노드의 책임을 다시 나눈 과정**이다. 새 문제마다 노드를 늘리기보다, 기존 노드의 역할을 재정의하는 게 더 나은 선택일 때가 있다는 걸 배웠다.

## ③ RAG 검색 실패 시 응답 전략 — "프롬프트냐 노드냐" 설계 의사결정 · ⭐⭐⭐⭐⭐

**문제 상황** · 사내 문서를 검색해 답하는 RAG에서, 문서에 관련 내용이 없을 때(no-hit) 어떻게 응답할지가 정해져 있지 않아 빈 context가 그대로 프롬프트에 들어가 부실한 답이 나갔다.

**여러 해결 방법 비교**

| 항목 | 프롬프트 내부 처리 | LangGraph 노드 분기 |
|---|---|---|
| 응답 속도 | 빠름(한 번에 처리) | 느림(재분기 필요) |
| 유지보수 | 쉬움 | 복잡 |
| 의도 제어 | "없으면 지식으로 답" 지시로 명확 | 흐름 중첩 위험 |
| 구현 난이도 | 낮음 | 높음(상태 추가 전달) |

**왜 프롬프트 처리인가** · no-hit는 별도 노드로 분기할 만큼 복잡한 상태 전이가 아니라, 프롬프트 한 곳에서 조건부 지시로 처리할 수 있는 케이스라고 판단했다. 노드를 늘리면 그래프만 복잡해질 뿐 얻는 게 없었다.

**핵심 코드**
```python
context = context.strip() or "※ 참고할 문서가 없습니다."   # 빈 검색결과를 명시적 신호로

# 프롬프트
"""아래 참고 자료를 우선 사용하되,
자료가 비었거나 답을 찾을 수 없으면 알고 있는 지식·상식으로 답해도 됩니다.
[참고 자료]
{context}"""
```

**적용 후** · 검색이 실패해도 응답이 비지 않고 지식 기반으로 이어진다. no-hit 처리를 위해 그래프에 노드를 추가하지 않아 흐름이 단순하게 유지됐다.

**배운 점** · RAG의 완성도는 잘 찾을 때가 아니라 못 찾을 때의 동작에서 갈린다는 것, 그리고 모든 예외를 노드로 쪼갤 필요는 없고 처리 위치(프롬프트 vs 그래프)를 비용 대비로 고르는 게 설계라는 걸 배웠다.

## ④ 사용자별·채팅방별 세션 메모리 구조 · ⭐⭐⭐⭐

**문제** · 한 사용자가 여러 채팅방을 오가고 여러 사용자가 동시에 쓰는데, 메모리가 전역 단일이면 대화 맥락이 섞인다.

**해결** · `(user_id, chat_id)` 튜플을 키로 세션을 격리하고, 조회는 `.get(key, [])`로 처리해 키가 없어도 `KeyError` 없이 빈 세션으로 시작한다. 저장 포맷은 dict 대신 `"사용자: …" / "소담이: …"` 화자 접두 문자열 리스트로 두어, `"\n".join()`하면 대화 스크립트 형태가 되도록 했다.

```python
chat_memory_store: Dict[Tuple[str, str], List[str]] = {}

def append_chat_memory(user_id, chat_id, question, answer):
    key = (user_id, chat_id)
    memory = chat_memory_store.get(key, [])   # 없으면 빈 리스트
    memory += [f"사용자: {question}", f"소담이: {answer}"]
    chat_memory_store[key] = memory
```

**적용 후** · 유저·채팅방별 맥락이 격리되고, 대화 스크립트형 포맷 덕에 "그 소·아까 그거" 같은 후속 질문의 맥락이 프롬프트에 자연스럽게 이어진다. LangChain 표준 메모리로 옮길 때도 문자열 리스트가 호환이 낫다.

**배운 점** · 메모리를 어떤 키와 자료구조로 들고 있느냐가 멀티턴 품질과 확장성을 좌우한다는 것, LLM에겐 dict보다 사람이 읽는 대화 텍스트가 더 잘 맞는다는 것.

## ⑤ RAG 출처 표기 반복 개선 · ⭐⭐⭐⭐

**문제** · 답변에 근거 문서 출처를 붙이기 시작하자 자잘한 오류가 이어졌다. 확장자가 그대로 노출(`무언가.pdf`)되고, 같은 문서가 중복 표기되고, `**` 같은 기호가 날것으로 나가고, 영어 질문에도 "출처:"가 한글로 붙었다.

**해결** · 문서 임베딩 시점부터 확장자를 뗀 파일명만 metadata에 저장하고, 출력은 중복 제거·기호 제거·질문 언어별 분기(`[출처]` / `[Source]`) 규칙으로 다듬었다. 커밋 `c2f4e1a → 5961f94 → 83f0337 → b945b5a → 5d29b8a`로 이어진 반복 개선이다.

```python
base_name = os.path.splitext(file_name)[0]   # 확장자 제거한 파일명만 metadata로
documents.append(Document(page_content=chunk, metadata={"source": base_name}))
```

**적용 후** · 출처가 깔끔한 파일명으로, 중복·기호 없이, 질문 언어에 맞춰 표기된다.

**배운 점** · 근거를 "보여주는 것"과 "보기 좋게 보여주는 것"은 별개이며, 사용자에게 닿는 마지막 한 줄까지 다듬는 게 제품 완성도다. 한 번에 끝나지 않고 여러 커밋에 걸쳐 관찰→수정을 반복한 과정 자체가 실무에 가깝다.

# 슬림버전 (카드용)

## ① 배포 환경 벡터 DB 생성 실패 & 재로딩 · ⭐⭐⭐⭐⭐
- **문제** — 로컬에선 되던 RAG가 배포 서버에서 Chroma DB 생성 실패, 캐시가 있어도 매 요청 재로딩됨
- **해결** — 절대경로 `/RAG/chroma` → 상대경로로 이식성 확보, 진입부 `_vectordb=None` 제거로 캐시 히트 분기 복원, 예외·빈문서 방어 추가
- **효과** — 로컬·배포 동일 동작, 첫 요청 이후 벡터 DB 재로딩 없음(반복 파일 접근·재임베딩 제거)
- `#배포환경` `#캐시` `#RAG`

## ② 질문 라우팅 아키텍처의 진화 · ⭐⭐⭐⭐⭐
- **문제** — 3분류 → `irrelevant` 추가했더니, UX 대화("아까 뭐랬어?")까지 무관 질문으로 오차단됨
- **해결** — 노드를 더 만들지 않고 역할 재정의: `rag`(지식 단일화)·`general`(UX 전담)·`cow_info`(지시어 흡수)·`irrelevant`(완전 무관만) + LLM 오출력 방어
- **효과** — 무관 질문은 LLM 호출 전 종료, UX 대화 오차단 해소, 의도별 데이터 소스 분리
- `#LangGraph` `#아키텍처진화` `#의도분류`

## ③ RAG 검색 실패 시 응답 전략 · ⭐⭐⭐⭐⭐
- **문제** — 문서에서 못 찾는 no-hit 케이스가 설계에 없어 빈 context로 부실 응답
- **해결** — '프롬프트 처리 vs 노드 분기'를 속도·유지보수·의도제어로 비교 → 프롬프트 fallback 채택("자료 없으면 지식으로 답")
- **효과** — 검색 실패에도 응답이 비지 않음, no-hit용 노드 없이 그래프 단순 유지
- `#RAG` `#Fallback` `#의사결정`

## ④ 사용자별·채팅방별 세션 메모리 · ⭐⭐⭐⭐
- **문제** — 전역 단일 메모리로 유저·채팅방 대화가 섞임, dict 저장은 LLM·LangChain 모두 불리
- **해결** — `(user_id, chat_id)` 키로 세션 격리 + `.get(key, [])` 안전 조회, 화자 접두 문자열 리스트로 저장
- **효과** — 맥락 격리·KeyError 제거, 대화 스크립트형 포맷으로 멀티턴 맥락 연결
- `#Memory` `#멀티턴` `#세션관리`

## ⑤ RAG 출처 표기 반복 개선 · ⭐⭐⭐⭐
- **문제** — 출처에 확장자·중복·기호 노출, 영어 질문에도 한글 "출처:"
- **해결** — 임베딩 단계에서 확장자 제거 파일명만 metadata 저장, 중복·기호 제거 + 언어별 `[출처]`/`[Source]` (커밋 5건)
- **효과** — 출처가 깔끔·정확·다국어로 표기됨
- `#RAG` `#응답품질` `#다국어`
